# TMC2209 в UART-режиме на MKS DLC32

Вариант прошивки `mks_dlc32_v2_1_tmc`: драйверы TMC2209 управляются шагами как обычно
(step/dir через I2S-регистр), а по UART настраиваются ток, микрошаг и StealthChop —
в любой момент, в том числе перед каждым заданием.

## Сборка и прошивка

```bash
cd Firmware
pio run -e mks_dlc32_v2_1_tmc            # сборка
pio run -e mks_dlc32_v2_1_tmc -t upload  # прошивка по USB
```

Обычный env `mks_dlc32_v2_1` не затронут: без флага `USE_TMC2209_UART` прошивка
идентична прежней (step/dir, coolant на месте).

## Проводка

UART-шина сидит на пинах **разъёма I2C** платы (паяться к ESP32 не нужно):

| Сигнал | Пин ESP32 | Куда |
|---|---|---|
| TX | IO0 (SDA-пин разъёма I2C) | через резистор **1 кОм** на общую линию PDN_UART |
| RX | IO4 (SCL-пин разъёма I2C) | на ту же линию PDN_UART напрямую |
| GND | GND разъёма I2C | общий с драйверами (уже общий через плату) |

Линия PDN_UART — общая для всех трёх драйверов: соединить пины PDN_UART модулей
X, Y, Z проводом и завести на неё TX (через 1 кОм) и RX.
Если связь с тремя драйверами неустойчива, уменьшить резистор до ~470 Ом.

```text
MKS DLC32 v2.1 — разъём I2C            общая линия PDN_UART
(подписи по шелкографии платы)
┌──────┐
│ SDA  │ = IO0 (TX) ──[1 кОм]──┐
│ SCL  │ = IO4 (RX) ───────────┤
│ GND  │ земля общая —         ├──────────┬──────────┬──────────┐
│ 5V   │ уже соединена платой  │          │          │          │
└──────┘ 5V НЕ подключать      │      PDN_UART   PDN_UART   PDN_UART
                                       модуль X   модуль Y   модуль Z
                                       MS1=GND    MS1=VIO    MS1=GND
                                       MS2=GND    MS2=GND    MS2=VIO
                                       адрес 0    адрес 1    адрес 2
```

Перед пайкой прозвонить разъём: пин с шелкографией **SDA** должен звониться на
GPIO0 модуля ESP32, **SCL** — на GPIO4 (в прошивке `IIC_SDA=0`, `IIC_SCL=4`).
Пин PDN_UART на степстике ищется по шелкографии модуля (обычно подписан
`PDN`/`UART`, часто два спаренных пина в левом ряду; у BTT-модулей есть
отдельное отверстие UART).

**PDN_UART на сокете**: перед пайкой прозвонить, куда разведён соответствующий
пин степстик-сокета DLC32. Если он посажен на GND/VCC — классика ретрофита:
отогнуть ножку PDN_UART у модуля (или не запаивать её в гребёнку) и паять
провод прямо к ней.

**Уровни**: убедиться, что VIO (логическое питание) модулей — **3.3 В**.
Если сокет кормит VIO пятью вольтами, TMC2209 будет отвечать 5-вольтовыми
уровнями прямо в GPIO4 ESP32 — так нельзя; питать VIO модулей от 3.3 В.

## Адреса драйверов (MS1/MS2)

В UART-режиме MS1/MS2 задают не микрошаг, а адрес на шине:

| Ось | Адрес | MS1 | MS2 |
|---|---|---|---|
| X | 0 | GND | GND |
| Y | 1 | VIO | GND |
| Z | 2 | GND | VIO |

Перемычки микрошага под сокетами DLC32 (если стоят) в UART-режиме работают как
задатчики адреса — выставить по таблице. Если MS-пины сокета зашиты наглухо не
так, как нужно, — отогнуть ножки MS1/MS2 модуля и задать уровень проводками.
Микрошаг при этом задаётся прошивкой (по умолчанию 16, настройка `$Axis/Microsteps`).

## Что меняется в прошивке

- Ток: по умолчанию run 0.8 А / hold 0.4 А (RMS), настройки `$X/Current/Run`
  (=$140-серия), `$X/Current/Hold` ($150), микрошаг `$X/Microsteps` ($160) —
  аналогично Y/Z; сохраняются в NVS, применяются сразу (можно менять перед
  каждым заданием по USB/Telnet/WebUI).
- Режим: StealthChop (тихий), задан на этапе компиляции
  (`TRINAMIC_UART_RUN_MODE` в machine-файле).
- Диагностика: при старте драйвер проверяет связь по UART и пишет в консоль
  результат; при проблемах (short to ground, перегрев) — warning. Если UART
  не отвечает, шаги всё равно работают (step/dir независимы).
- **Coolant (M7/M8) недоступен** — его пины (IO0/IO4 на разъёме I2C) заняты шиной.
  Если нужен air assist по M8 — этот вариант прошивки не подходит без переноса пина.

## Ограничения

- Sensorless homing (StallGuard) не включён: для него нужно дополнительно завести
  выход DIAG каждого драйвера на вход соответствующего концевика.
- IO0 — strapping-пин ESP32: при прошивке по USB шина TMC не мешает (PDN_UART
  линию никто активно не тянет), но если что-то внешнее будет держать IO0 низким
  при сбросе — плата уйдёт в bootloader. Не вешать на линию лишнего.
