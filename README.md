# MKS-DLC32-FIRMWARE — CNC-форк с TMC2209 по UART
[![Boosty](https://img.shields.io/badge/Boosty-Buy_me_a_coffee-FF7143?logo=boosty&logoColor=white&style=for-the-badge)](https://boosty.to/danusha/donate)

Прошивка контроллера **MKS DLC32 v2.1** (ESP32) для ЧПУ-станка со шпинделем:
**без экрана**, с драйверами **TMC2209 в UART-режиме** — ток, микрошаг и тихий
StealthChop настраиваются командами по USB/Wi-Fi, без перемычек и подстроечников.

Форк ветки `MKS-DLC32-NEW-CNC` от [IDLEVEL/MKS-DLC32-FIRMWARE](https://github.com/IDLEVEL/MKS-DLC32-FIRMWARE),
которая основана на брошенной официальной прошивке
[makerbase-mks/MKS-DLC32-FIRMWARE](https://github.com/makerbase-mks/MKS-DLC32-FIRMWARE)
(движок Grbl_ESP32 v1.1). Прошивка переведена на **arduino-esp32 2.0.17**
(espressif32 6.12.0, ESP-IDF 4.4.7) с серией фиксов стабильности — разбор в
[`docs/MIGRATION_6X.md`](docs/MIGRATION_6X.md), технические заметки форка — в
[`docs/FORK_NOTES.md`](docs/FORK_NOTES.md).

## Конфигурация этой ветки

- **Экран не используется.** Станок управляется по USB, Telnet, WebUI в браузере
  или Android-приложением — панель TS35 в этой конфигурации не нужна.
- **TMC2209 по UART**: общая шина на пинах разъёма I2C платы. Из-за этого:
  - выходы **coolant M7/M8 недоступны** (их пины заняты шиной);
  - **внешний пульт IDLEVEL несовместим** с этим вариантом (использует те же IO0/IO4);
  - нужна небольшая **навесная обвязка согласования уровней** (логика драйверов на
    плате пятивольтовая) — см. ниже.
- Шаги идут как обычно (step/dir через I2S-регистры): UART нужен только для
  настройки, при потере связи с драйвером движение не останавливается.

## Целевое железо

- Плата: **MKS DLC32 v2.1** — ESP32-WROOM-32U (8 МБ flash, 520 КБ RAM), степперы
  через I2S-сдвиговые регистры. Полная спека — [`docs/BOARD_SPEC.md`](docs/BOARD_SPEC.md).
- Драйверы: 3× **TMC2209** (степстики) в сокетах платы.
- Назначение: **ЧПУ-фрезер** (3 оси XYZ, шпиндель с PWM).

Карта пинов задаётся в `Firmware/Grbl_Esp32/src/Machines/i2s_out_xyz_mks_dlc32.h`
(флаги `USE_BOARD_V2_0` + `USR_Z_MOTOR` + `USE_TMC2209_UART`):

| Функция | Пин |
|---|---|
| Шпиндель PWM | GPIO32 |
| Probe | GPIO22 |
| Концевики X / Y / Z | GPIO36 / GPIO35 / GPIO34 |
| Степперы X/Y/Z (step/dir) | I2S (BCK16 / WS17 / DATA21) |
| Шина TMC2209 UART | TX=IO0, RX=IO4 (пины разъёма I2C) |
| SD-карта | SPI: SCK14, MISO12, MOSI13, CS15; детект GPIO39 |

Все 3 оси полноценные (движение/джоггинг/probe/обнуление по Z работают).
Авто-хоминг по Z выключен в дефолтах (`$22=0`) — включается через настройки или
`DEFAULT_HOMING_ENABLE 1` + `DEFAULT_HOMING_CYCLE_1 (bit(Z_AXIS))`.

## TMC2209: подключение и настройка

Коротко (полная инструкция с номиналами и граблями —
[`docs/TMC2209_UART.md`](docs/TMC2209_UART.md)):

- ⚠️ **Напрямую проводом подключать нельзя.** На DLC32 логика шаговой части
  пятивольтовая: VIO степстика (пин 7 сокета) жёстко разведён на **+5V**,
  step/dir/en приходят с 74HC595, запитанного 5 В, а EN ещё и подтянут к +5V
  резисторами R31–R33. У TMC2209 порог «1» равен `0.7 × VIO` = **3.5 В** (3.3 В
  с ESP32 недостаточно), а отвечает он уровнем VIO = 5 В — прямо в GPIO ESP32,
  у которого абсолютный максимум ~3.6 В. Нужен преобразователь уровней на одной
  UART-линии: два копеечных буфера с фиксированным направлением (`SN74AHCT1G125`
  с питанием 5 В на TX и `SN74LVC1G17` с питанием 3.3 В на RX — у последнего вход
  толерантен к 5.5 В), либо один `TXU0202`. Плату при этом переделывать не надо.
  Разбор всех вариантов (в том числе почему не годится «перевести VIO на 3.3 В»
  и почему нельзя понизить сам источник 5 В) —
  в [`docs/TMC2209_UART.md`](docs/TMC2209_UART.md).

  ```text
  разъём I2C DLC32                                       общая линия PDN_UART
  (1=+3V3, 2=GND, 3=SDA=IO0, 4=SCL=IO4)
                     ┌────────────────────────┐
   SDA = IO0 (TX) ──►│ SN74AHCT1G125, VCC=+5В │──[1 кОм]──┐
                     │ OE# → GND              │           │
                     └────────────────────────┘           ├───────┬────────┬────────┐
                     ┌────────────────────────┐           │       │        │        │
   SCL = IO4 (RX) ◄──│ SN74LVC1G17, VCC=+3.3В │◄──────────┘   PDN_UART PDN_UART PDN_UART
                     └────────────────────────┘               модуль X модуль Y модуль Z
   GND ── общий                                               (пины RST/SLP сокета)
   +5 В для обвязки — с EXP1 (пин 10), экран не используется
  ```

  На разъёме I2C пин питания — **+3V3, не 5 В**; подключать его никуда не нужно.
- PDN_UART у степстиков SilentStepStick v2.0 выведен на позиции сокета
  **RST/SLP**, а DLC32 соединяет эти два пина между собой и больше никуда —
  провод шины паяется прямо к площадке сокета, ножки отгибать не нужно.
- Шина одна на все три драйвера: адрес получателя прошивка вписывает в каждый
  пакет. Адрес задаётся пинами **MS1/MS2** (в UART-режиме это адресные биты, а не
  микрошаг), которые на DLC32 выведены на штатные DIP-переключатели:

  | Драйвер в сокете | Адрес | Поз. 1 (MS1) | Поз. 2 (MS2) | Поз. 3 |
  |---|---|---|---|---|
  | X (`SW1`) | 0 | OFF | OFF | OFF |
  | Y (`SW2`) | 1 | **ON** | OFF | OFF |
  | Z (`SW3`) | 2 | OFF | **ON** | OFF |

  Позиция 3 — это не MS3, а **SPREAD**: включённая даст SpreadCycle вместо
  StealthChop, держать OFF.

  Принадлежность мотора к оси задаёт **сокет** (step/dir), адрес — только кому
  уйдут настройки тока/микрошага. Перепутанный адрес не поменяет оси местами,
  но настройки «для X» молча применятся к чужому мотору, поэтому: драйвер в
  сокете X обвязывается на адрес 0, в Y — 1, в Z — 2. Два одинаковых адреса =
  оба молчат (CRC-ошибки), прошивка сообщит при старте. Проверка раскладки:
  `$X/Current/Run=0.1` → момент должен потерять именно X-мотор; повторить для Y/Z.
- Настройки в прошивке: ток `$X/Current/Run` (серия `$140`), удержание
  `$X/Current/Hold` (`$150`), микрошаг `$X/Microsteps` (`$160`) — аналогично Y/Z.
  Хранятся в NVS, применяются сразу: можно менять хоть перед каждым заданием.
  `$X/Current/Run=0` выключает ток; микрошаг принимается только из ряда
  0/2/4/8/16/32/64/128/256.
- Режим — StealthChop (тихий), задан на этапе компиляции.
- При старте прошивка проверяет связь с каждым драйвером и пишет результат в
  консоль; предупреждает о short-to-ground и перегреве.

> ⚠️ Вариант TMC2209 UART собран и проверен компиляцией, но **на живом станке
> ещё не гонялся** — базовой прошивки это не касается.

## Сборка

Нужен [PlatformIO Core](https://platformio.org/) (или расширение PlatformIO в VS Code).

```bash
cd Firmware
pio run -e mks_dlc32_v2_1_tmc            # сборка TMC-варианта
pio run -e mks_dlc32_v2_1_tmc -t upload  # прошивка по USB
```

Артефакт: `Firmware/.pio/build/mks_dlc32_v2_1_tmc/firmware.bin`.

Окружения (`Firmware/platformio.ini` + `Firmware/ini/mks_dlc32.ini`):

| env | Назначение |
|---|---|
| `mks_dlc32_v2_1_tmc` | **Основное для этой ветки**: TMC2209 по UART. Партиция `esp32_8MiB.csv` (2× OTA-слота по 3 МБ) |
| `mks_dlc32_v2_1` | Базовый вариант без TMC UART (драйверы в обычном step/dir-режиме, coolant на месте) |
| `mks_dlc32_v2_1_ota` | Загрузка по воздуху (espota, IP в `ini/mks_dlc32.ini`). ⚠️ Собирает **базовый** вариант — для OTA TMC-варианта добавьте в env флаг `-D USE_TMC2209_UART` |

Готовые бинарники в [`release/`](release/) (со скриптами `flash_usb.sh`/`.bat`)
тоже собраны из **базового** варианта — TMC-вариант собирайте из исходников.

## Тесты

Чистую логику (без зависимостей от железа) покрываем нативными unit-тестами:

```bash
cd Firmware
pio test -e native
```

Тесты лежат в `Firmware/test/`. Сейчас покрыт классификатор политики SD↔USB
(`line_safe_during_sd_job`, см. `test/test_sd_job_policy/`).

## Статус

Базовая функциональность **проверена на реальной плате MKS DLC32 v2.1**
(ESP32-D0WD, flash 8 МБ) — протокол испытаний в
[`docs/CODE_REVIEW.md`](docs/CODE_REVIEW.md). Проверка велась на голой плате
(USB): пункты, требующие собранного станка — лимиты/хоминг/движение/джоггинг/
probe/SD-печать со «Стоп» — собраны в
[`docs/MIGRATION_6X.md`](docs/MIGRATION_6X.md#-что-надо-протестировать-на-железе).

- ✅ Собирается на Linux/Mac/Windows.
- ✅ Wi-Fi: событийный авто-реконнект STA, self-heal из AP-fallback, mDNS в AP и
  STA (`http://mks-dlc32.local`). Сеть — WPA2 2.4 ГГц (WPA3-only ESP32 не умеет).
  Ping-soak 60 c = 0% потерь.
- ✅ OTA по воздуху: партиция под реальные 8 МБ, два app-слота по 3 МБ.
- ✅ SD ↔ USB/сеть: во время задания с карты со второго интерфейса проходят
  realtime и read-only запросы (`?`, `$$`, `$G`…), движение отклоняется
  `error:120` **без обрыва задания**.
- ✅ WebUI: канал WebUI↔ядро жив, большие ответы не теряются; имя устройства
  `mks-dlc32`, меняется в WebUI.
- ✅ Telnet, HTTP-загрузка файлов на SD (`/upload`). Карта — только FAT32
  (exFAT не монтируется — карты >32 ГБ переформатировать). Во время задания с SD
  загрузка нового файла намеренно блокируется — заливать до запуска.
- ✅ Удалённое управление через центральный сервер: плата сама подключается к
  нему по TCP (`$Remote/Server`, `$Remote/Token`, `$Remote/Name`, хранятся в
  NVS) — инструкция в [`docs/REMOTE_CONTROL.md`](docs/REMOTE_CONTROL.md).
- ⏳ TMC2209 UART: собрано, ждёт проверки на железе (см. выше).
- 🔜 По умолчанию аутентификация выключена — смените пароль AP в WebUI.
